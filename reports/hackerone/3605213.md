## Impact

The exposed REST API discloses the following security risks:

**1. Plugin Enumeration:**
- All installed plugins are disclosed via the `namespaces` array
- Attackers can research specific plugin versions for known CVEs
- Enables targeted exploitation of vulnerable plugins

**2. Site Structure Disclosure:**
- Homepage ID, logo ID, and icon ID are exposed
- Attackers can enumerate content structure
- Facilitates targeted attacks on specific pages/posts

**3. Authentication Method Exposure:**
- Application passwords capability is disclosed
- Attackers know authentication endpoints are available
- Can be leveraged for credential-based attacks

**4. Reconnaissance Enablement:**
- Full WordPress configuration is visible
- Timezone, GMT offset, and site settings disclosed
- Aids in planning more sophisticated attacks

**5. Compounding Issues:**
- 150+ WordPress admin files are accessible (see gobuster-results.txt)
- Multiple server errors (500) indicate misconfiguration
- Combined with REST API exposure, significantly increases attack surface

**Business Impact:**
- Increased risk of targeted attacks on [REDACTED-VENDOR] Labs website
- Potential for plugin exploitation leading to site compromise
- Reputation damage if site is compromised
- Violation of security best practices (WordPress hardening guidelines)

## Analyst Response

**[REDACTED-ANALYST]** (March 18, 2026, 12:23pm UTC):
> "Thank you for your report!
> 
> Exposing the /wp-json endpoint publicly is not inherently a security risk because it mainly exposes data that is already public. The majority of data exposed through WordPress' REST API is already publicly available through the website itself. For example, data like published posts, pages, categories, tags, and basic site information are visible to any visitor, whether they use the API or browse the site directly.
> 
> The WordPress API only exposes sensitive or private data (like draft posts or user information) when a request is authenticated. Only users with proper permissions (such as logged-in administrators or editors) can access or modify private data through the API. Authentication methods typically include Cookies (when logged in), OAuth, and API keys or tokens (for custom applications).
> 
> For further context, you can review the WordPress API documentation here: https://developer.wordpress.org/rest-api/key-concepts/#routes-endpoints
> 
> We encourage you to keep submitting your findings, as your contributions help improve security awareness.
> 
> Kind regards,
> [REDACTED-ANALYST]"
